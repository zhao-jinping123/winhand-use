# 权限与故障排查（Windows 版）

## 一、Windows 没有 TCC，但有 UIPI

macOS 要授权屏幕录制/辅助功能；Windows 的读（窗口枚举、PrintWindow、UIA）**不需要任何授权**，普通用户态即可。真正的墙是 **UIPI（用户界面特权隔离）**：

- 以**管理员/更高完整性级别**运行的进程，普通权限的 agent 读不到它的 UIA 树、SendInput/PostMessage 也打不进去（错误或静默无效）。
- 症状：`win ax` 树为空、`op` 借焦点后无反应、点不动。
- 出路：让 agent 也以管理员运行（同一完整性级别），或把该 app 降权运行；**不要试图绕 UIPI**。

## 二、锁屏 / 安全桌面 / 无交互会话

| 场景 | 表现 | 处理 |
|---|---|---|
| 锁屏（Win+L / 屏保接管） | `GetForegroundWindow` 返回 lockapp/锁屏软件；截图黑/失败；SendInput 无效 | 标「此步需人在场」，不假装能截 |
| UAC 弹窗、Ctrl+Alt+Del | 安全桌面，普通 API 全部失效 | 同上；永远不碰 UAC 确认 |
| agent 跑在服务/计划任务（无交互会话） | SetForegroundWindow 永远失败 | 只能走 CDP/L0/UIA 后台；GUI 点击不可用 |

无人值守跑批的纪律：先 `win idle` 看人在不在；锁屏状态下所有「借焦点」动作直接拒绝。

## 三、虚拟桌面与最小化

- `win windows` 输出 `on=1/0` 表示窗口是否在**当前虚拟桌面**（IVirtualDesktopManager 判定，内核已内置）。
- 坐标写操作（全局流）对 `on=0` 的窗口直接拒绝（`refused: cross-desktop`）——不是点不到，是会**点到你正在用的窗口上**。出路：CDP，或请用户把窗口挪过来。读（PrintWindow）多数跨桌面可用，实测为准。
- 最小化窗口：rect 是 `(-32000,-32000,宽,高)`，PrintWindow 失败/空图。先 `win shot` 诊断输出，别盲试。

## 四、DPI 与多显示器

- 内核启动即 `SetProcessDPIAware()`；不设的话 150% 缩放下 rect 与截图像素不一致，坐标系统性偏移。
- **多显示器不同缩放**：物理像素全局一致（DPI 感知后），窗口可能一半在 100% 屏一半在 150% 屏；截图按窗口 DWM rect 走，仍然自洽。
- 变更显示缩放/拔插显示器后，窗口 rect 会变，重新 `win see`。

## 五、环境坑

- 🔴 本机跑 Clash 类代理时，curl 本机端口必须 `--noproxy "*"`（cdp.js 已设 NO_PROXY；probe 里的 curl.exe 调用都带）。否则误判「app 没开调试服务」。
- **杀毒/安全软件**可能拦截 SendInput、剪贴板访问、对特定进程的注入式操作。症状是工具返回成功但没生效，或直接弹安全提示。换 UIA/CDP 路径或让用户加白。
- **输入法**：SendInput 走 `KEYEVENTF_UNICODE` 不经过输入法，稳定；UIA SetValue 也不经输入法。剪贴板路径会受输入法无关的剪贴板占用影响。
- PowerShell 5.1 脚本必须 UTF-8 **带 BOM** 保存，否则中文被按 ANSI 解析成乱码（本项目 .ps1/.cs.inc 都已处理；改文件后记得保持）。

## 六、四道闸（不打扰用户的实现）

| 闸 | 拦什么 | 覆盖 |
|---|---|---|
| 前台闸 | 全局键鼠打给的不是目标 → 拒绝 | `type`/`key` 全局档 |
| 遮挡闸 | 落点最上层不是目标窗口 → 拒绝 | 借焦点前的 `WindowFromPoint` 检查 |
| 在场闸 | 用户 2 秒内动过键鼠 → 静等停手，最多 15 秒，等不到拒绝 | 所有借焦点动作 |
| 借焦点锁 | 全机同时只允许一个借焦点者（`Local\winhand-use-focus-v1` 互斥体） | `op`/`click`/`shot --fg` |

`--force` 拆全部闸；`--dry` 零执行但报出每道闸判定。PostMessage 后台档本来就不碰前台，不设闸。

### 三个非踩不可知的实现细节

1. **自己合成的事件会刷新系统空闲计时器。** `SendInput`/`SetCursorPos` 后 `GetLastInputInfo` 的空闲秒数掉回 0，不处理会让下一条命令误判「用户在动」而自锁。内核把每次自身合成的 tick 写进 `%TEMP%\winhand-use-selfinput.txt`，在场闸读数与它吻合（<1.2 秒）就排除自身痕迹。
2. **`type`/`key` 全局档打给「当前前台窗口」，pid 参数只用于回显。** 前台随时会被用户切走，pid 传对不等于打对地方。前台闸就是为这个加的：前台不是目标就拒绝并告诉你当前前台是谁。
3. **`--dry` 必须走完闸再退出。** 只解析坐标就 exit 的 dry 没法预演「这一下会不会被拦」，拒绝分支只能拿真命令试——而条件不满足时它就真执行了。

## 七、截图失败归因（自诊断顺序）

`win shot` 先 PrintWindow（`PW_RENDERFULLCONTENT` 优先，失败退回普通模式），然后分析像素：

1. `fail:invalid-hwnd` → 窗口已关，重新 `win windows`。
2. `fail:zero-size` 或 rect 在 `-32000` 附近 → 最小化。还原（非激活）后再截。
3. 空图/全黑（`black>0.98` 且颜色数 <4）→ 三种可能：窗口未渲染（后台启动的 Chromium 标签页没画过）、被独占全屏盖住、锁屏。先试 `--fg` 借焦点；不行就换 CDP 截图或如实报告。
4. 窗口级 PrintWindow 对**取证**足够（不包含 HUD）；若必须桌面全屏取证且 HUD 在显示，等 HUD 结束（1 秒内）再截。

## 八、HUD 三条约束

借焦点那一两秒用户看到的是窗口自己跳前面，不解释就是「见鬼了」。HUD 约束：

| 约束 | 实现 | 破了会怎样 |
|---|---|---|
| 鼠标穿透 | WS_EX_TRANSPARENT | 提示框挡住用户点击 |
| 永不抢焦点 | WS_EX_NOACTIVATE + ShowActivated=false | 为了提示「要抢焦点」先抢了焦点 |
| 短暂 | 1 秒自动关 | 常驻框本身成为干扰 |

Windows 没有 macOS 的「对屏幕捕获隐身」；窗口级 PrintWindow 截图天然不含 HUD（只画目标窗口），桌面全屏捕获会带上。取证截图一律用窗口级。
