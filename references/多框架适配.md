# 多 agent 框架适配：为什么它能在任何框架里跑

本技能遵循 **Agent Skills 开放协议**：一个文件夹 + `SKILL.md`（frontmatter 的 `name`/`description` 供框架发现）。框架只负责把 SKILL.md 内容喂给模型、把 shell 命令交给你执行——**本技能不依赖任何框架 API、不需要特定语言运行时**，全部能力走一条命令：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "<技能目录>\scripts\win.ps1" <命令> ...
```

因此只要框架满足两个条件就能用：能读 SKILL.md（或你把关键指令粘进系统提示），能执行 shell 命令。

如果客户端是 MCP-only（不方便读 SKILL.md），也可以用仓库自带的零依赖 MCP Server：
`node mcp/server.js` 会暴露 18 个工具（`win_doctor` / `win_see` / `win_ax` / `win_op` …），
配置示例见 [../mcp/README.md](../mcp/README.md)。

## 各框架安装位置

| 框架 | skills 目录（没有就自建） | 备注 |
|---|---|---|
| Codex | `~/.codex/skills/winhand-use` | 本项目已装好，自动发现 |
| Claude Code | `~/.claude/skills/winhand-use` | 完整读 SKILL.md |
| Cursor | `~/.cursor/skills/winhand-use` 或项目 `.cursor/skills/` | 新版支持 Agent Skills |
| Kimi Code / ZCode / 豆包工作等 | 各自文档里的 skills 目录，通常是 `~/.<产品名>/skills/` | 装完先 `win doctor` |
| Hermes / DeepSeek harness 等自研框架 | 无标准目录时：把 SKILL.md 全文放进系统提示，或做成工具描述 | 命令调用方式不变 |

通用一句话安装（任何框架的 agent 会话里）：

```
把 C:\Users\赵晋平\.codex\skills\winhand-use 整个文件夹复制到你的 skills 目录，然后执行:
powershell -NoProfile -ExecutionPolicy Bypass -File "<技能目录>\scripts\win.ps1" doctor
```

## 每个 runtime 首次使用前：win doctor

`win doctor` 输出环境自检（OS/PS 版本、内核编译、窗口枚举、前台状态、UIA 探针、node 可用性、焦点锁），exit 0 = 环境可用。不同框架跑同一个命令，输出应该一致——不一致就是框架的 shell 环境问题（见下）。

## 已知跨框架坑与对策

1. **必须用 `powershell.exe`（Windows PowerShell 5.1），不是 `pwsh`**。UIA 依赖 .NET Framework 程序集。Claude Code/Cursor 在 Windows 上默认的 shell 若是 git-bash，直接写 `powershell -NoProfile ... -File ...` 即可；若是 pwsh，命令不变（pwsh 里调 powershell.exe）。
2. **用全路径调用**。agent 的 cwd 是用户项目目录，不是技能目录。SKILL.md 里所有脚本都以 `$SKILL_DIR`（技能目录绝对路径）开头。
3. **退出码三态是给框架的**：0 成功 / 1 失败 / 2 拒绝或未知。agent 看到 2 要读输出判断是「refused」（闸拒绝/跨桌面/锁屏）还是「unknown」，不要重试硬闯；看到 1 先看错误再决定。
4. **参数里的中文/emoji/空格**：经 `powershell.exe -File` 传参是 Unicode 安全路径；唯一禁忌是框架把命令拆成字节级再拼（极少见）。遇到乱码先 `win doctor` 对比，再怀疑框架 shell 编码。
5. **🔴 中间层是 PowerShell 5.1 时必须先设 UTF-8**：如果框架/胶水脚本（比如你的 wrapper 是 .ps1）调用 `win.ps1` 并捕获 stdout，先执行 `[Console]::OutputEncoding=[Text.Encoding]::UTF8; $OutputEncoding=[Text.Encoding]::UTF8`，否则 UTF-8 字节被按 GBK 解码，中文首字符会出现 `s`/`shi` 这类错位（2026-09-07 实测）。直接 `powershell.exe -File win.ps1` 无此问题（win.ps1 内部已设置）。
6. **长文本入参**（比如给输入框贴一大段代码）：部分框架对命令长度有限制。超过 ~2000 字符的文本，先写入临时文件，再让目标 app 打开/粘贴（UIA SetValue 不受命令长度影响时仍优先）。
7. **`win.cmd` 是给 cmd 的入口**；在 PowerShell/bash 里可以直接调 `win.cmd`，但要确保路径引号正确。跨框架最稳的永远是 `powershell.exe -File win.ps1` 全路径。
8. **输出编码**：内核已把 stdout 设为 UTF-8；框架按 UTF-8 解析即可，中文正常。PowerShell 5.1 的 `Write-Host` 诊断走信息流，部分框架只捕获 stdout——所以**关键结果全部走 stdout**（Write-Output），Write-Host 只用于 `--dry` 预演这类辅助信息。
9. **不要并行借焦点**：全机借焦点锁（`Local\winhand-use-focus-v1`）保证同一时刻只有一个 agent 能借焦点；多个 agent 同时跑时，后台读/UIA/CDP 互不打架，只有借焦点动作会排队/被拒（exit 2），这是设计不是故障。

## 如果框架连 SKILL.md 都不读

把 SKILL.md 的命令表 + 停手线 + 「四层控制面/读写分离/回读取证」三段直接写进该框架的系统提示或工具说明，脚本照样调用。技能的价值 80% 在指令质量，20% 在脚本。

## 适配自检清单（改完框架后跑一遍）

```powershell
# 1) 环境
win doctor
# 2) 只读链路
win windows 记事本
win shot <hwnd> 测试.png
win ax <hwnd>
# 3) 后台写链路（对自家沙盒窗口，别动用户文件）
win axset <hwnd> e0 "测试"
# 4) 退出码
echo $LASTEXITCODE   # 成功应为 0；故意打错目标应得 2
```
