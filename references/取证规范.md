# 取证规范——截图怎么命名、放哪、怎么合规、怎么能重跑

## 一、三套命名，按「这张图给谁看」分

- **过程图/给模型自己看**：`<步骤>-<序号>.png`，如 `op-before-1.png`、`shot-发送后.png`。留在会话临时目录或项目 `.work/`。
- **交付图/给用户看**：中文语义名，如 `Blender-甜甜圈-渲染对比.png`。
- **台账**：多轮跑批时每张图一行记录（时间、窗口、动作、结果判定）。

## 二、目录落位

截图落**项目目录**，不落桌面。建议结构：

```
<项目>/
├── shots/           # 原始取证图，永远保留
├── shots/_archive/  # 归档（只移动，不删除）
└── 交付/            # 加工后的成品
```

🔴 **原图与加工件分离**：压缩、裁剪、打码都生成新文件，原图只 `Move-Item` 进 `_archive/`，**绝不删除**。重截永远比找回容易，但「这张图是怎么来的」必须能重放。

## 三、尺寸、格式、压缩

- 正文插图：JPG、长边 ≤1600、<500KB。
- 取证原始图：PNG 不压缩（`win shot` 输出即原始）。
- 压缩/改尺寸用项目现成工具或 `image-compress`，不要现场写循环。

## 四、🔴 合规裁剪与打码

- 截图里出现**未发布代号、友商名、私人信息、密钥**，先问项目根目录禁词表；没有就按常识判断。
- 给用户/外发的图必须打码或裁剪后再放交付目录。
- UIA 元素摘要在 `win ax` 里已自动截断长文本（Document 只报字符数），避免把文件全文灌进对话；需要读全文用截图或显式读回。

## 五、多模型同题跑批

- 默认不产出横向对比和排名；用户要才做。
- 每轮同题跑批必须同窗口尺寸、同 app 版本、同输入，否则结果不可比。
- 采集期不丢指标：每轮记录 `effect=` 判定、截图差分、借焦点秒数。

## 六、产物落点定位

自动化产物（渲染图、报告）落到项目可预期目录，并在汇报里给**绝对路径**。测试窗口/临时文件用后即清，不留垃圾在用户桌面。

## 七、重跑重截的硬约束

- 每轮动作前先截 before，动作后再截 after——没有差分就不算验证过。
- 汇报里每张图注明：目标窗口、动作命令、`effect=` 判定、截图时间。
- 窗口移动/改版后旧坐标一律重截重量，不套档案。

## 八、已知缺口（未实现，动手前先问用户）

- Windows.Graphics.Capture 后台截 GPU 独占内容的兜底尚未接入内核（当前 PrintWindow 为主，黑屏时走 `--fg`）。
- 跨虚拟桌面的坐标写操作当前直接拒绝（CDP 除外）。
- OCR/批量翻旧截图交给 disk-keeper 类工具，不在本技能范围。
